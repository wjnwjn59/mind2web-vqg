# `outputs/` — Run results (do NOT commit)

Everything produced by eval/train ends up here. The folder is blocked by `.gitignore`
(except `.gitkeep`).

## Current layout

```
outputs/
├── eval_<split>/
│   └── predictions.json     # written by `uv run m2w-eval`
├── render_check/<split>/    # written by `uv run m2w-render-html`
│   ├── <id>_raw.jpg, <id>_cleaned.jpg, <id>_mm.jpg
│   └── index.html           # side-by-side gallery, open this in a browser
└── smoke_vlm/<split>_<timestamp>/   # written by `uv run m2w-vlm-smoke`
    ├── results.jsonl        # one line per (screenshot, probe)
    └── report.md            # markdown table of answers
```

For example: `outputs/eval_test_task/predictions.json`.

## What's inside `predictions.json`?

A list where each item is one predicted example:

```json
[
  {
    "id": "task1:0::target_label",
    "input": "You are shown a screenshot... The user's task is: ...",
    "target": "What text is shown on the button the user needs for the task \"...\"?",
    "answer": "Search",
    "image": "data/processed/multimodal/test_task/images/....jpg",
    "meta": { "category": "target_label", "website": "...", "domain": "..." },
    "prediction": "the question generated by the model"
  }
]
```

Note: `input` / `target` / `answer` / `image` come from `data/vqg.py` (via
`data/prepare.py::build_examples`), which expands each screenshot into one example per
applicable category.

## What's inside `results.jsonl` (smoke test)?

One line per probe, so you can compute anything later:

```json
{"id": "annot-0:0", "probe": "how_next", "probe_type": "how",
 "question": "The user's task is: ...\nWhat is the next action ...",
 "answer": "...", "seconds": 3.4, "image": "...", "target_action": "CLICK [Search]"}
```

`target_action` is the ground-truth action (from `target_action_reprs`) — not used for scoring
yet, but it is exactly what a later "did the question help?" metric would need.

## Planned additions

- `outputs/eval_<split>/metrics.json` — BLEU / ROUGE / LLM-as-judge (not implemented yet).
- `outputs/train/` — checkpoints once the fine-tuning pipeline exists (the `train.output_dir`
  field in `configs/default.yaml`; `train.py` currently only prints it).

## Tips

- To compare runs, copy `predictions.json` under a clearer name next to its config, e.g.
  `outputs/eval_test_task/predictions_api_gpt4omini.json`.
- Don't hand-edit files here expecting them to be tracked — they're ignored.
- Feel free to delete `outputs/eval_*`; rerunning `uv run m2w-eval` recreates them.
