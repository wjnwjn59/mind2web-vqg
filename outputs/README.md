# `outputs/` — Run results (do NOT commit)

Everything produced by eval/train ends up here. The folder is blocked by `.gitignore`
(except `.gitkeep`).

## Current layout

```
outputs/
└── eval_<split>/
    └── predictions.json     # written by `uv run m2w-eval`
```

For example: `outputs/eval_test_task/predictions.json`.

## What's inside `predictions.json`?

A list where each item is one predicted example:

```json
[
  {
    "id": "the instance annotation_id",
    "input": "content fed to the model",
    "target": "expected answer (currently empty)",
    "meta": { "website": "...", "domain": "..." },
    "prediction": "the question generated by the model"
  }
]
```

Note: `input`/`target` come from `data/prepare.py::build_examples`, so right now
`input` is just `confirmed_task` and `target` is an empty string.

## Planned additions

- `outputs/eval_<split>/metrics.json` — BLEU / ROUGE / LLM-as-judge (not implemented yet).
- `outputs/train/` — checkpoints once the fine-tuning pipeline exists (the `train.output_dir`
  field in `configs/default.yaml`; `train.py` currently only prints it).

## Tips

- To compare runs, copy `predictions.json` under a clearer name next to its config, e.g.
  `outputs/eval_test_task/predictions_api_gpt4omini.json`.
- Don't hand-edit files here expecting them to be tracked — they're ignored.
- Feel free to delete `outputs/eval_*`; rerunning `uv run m2w-eval` recreates them.
